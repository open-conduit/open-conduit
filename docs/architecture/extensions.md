# Extension, execution and observability contracts

Decision B03 · ticket 01-03. Public Go contracts live in [extension](../../extension/ingress.go) and [observability](../../observability/observability.go); [shared conformance cases](../../conformance/extensions.go) run against [volatile reference doubles](../../conformance/reference). These supplement [B02](domain-storage.md). They do not implement a runtime, a service integration or the later subprocess protocol.

Implementation note: the PRD's Sequence lists four interfaces, but its Cross-cutting contracts also requires observability. Observability is a **required fifth cross-cutting contract**, alongside ingress, executor, toolbelt and storage. It is not a sixth primitive. Actual OpenTelemetry instrumentation/export wiring arrives in 02-08; this ticket defines the correlation and reporting boundary without adding an SDK dependency.

## Ingress identity, observations and recovery

An ingress implements both `Push` and `Reconcile`, even if its only family is explicitly non-re-derivable (in that case reconcile may return an empty complete snapshot). Its registration declares each event family as recoverable or gives a concrete loss limitation. An arbitrary one-shot POST without readable backing history is not recoverable. GitHub push, release and workflow-run families must each establish actual readable history, permissions, retention and recovery horizon in 03-01/05-01; a service-wide recoverability claim is insufficient. This ticket uses synthetic state-change and one-shot families and makes no service-specific recovery claim.

`Source.Namespace` is a stable configured account/resource namespace. Scope is supplied by trusted configuration. Account identifiers, not credentials, determine identity; changing credentials cannot generate new logical events. Two scopes watching the same external source must coordinate ownership rather than silently duplicate it by changing its identity. B02 correlation ownership remains global within that namespace.

An observation contains an opaque item ID, an equality-only version token and its canonical Event. Adapters normalize payloads, timestamps, event family and canonical `(source, delivery_id)` identically for push and reconcile. The version must distinguish recurring transitions such as A → B → A; a content hash alone cannot identify both occurrences. Occurrence time is external time; receipt time reflects actual receipt and need not be identical across real transports. Internal Event ID/receipt time are not dedup identity: B02 returns the first accepted envelope on overlap. The synthetic fixtures use identical timestamps to check deterministic normalization. Multiple distinct events in one delivery get distinct stable delivery IDs (for example delivery/item/change); thread correlation never serves as event identity.

Recoverable push deliveries yield observations. Non-re-derivable families yield direct Events and explicitly disclose what is lost before acceptance. All emitted families must be declared. Push normalization and reconciliation perform no coordination writes. Their return values do not acknowledge acceptance: core validates the envelope and declarations, accepts durably, and only then acknowledges the delivery. Transport authentication and HTTP response mapping belong to service implementations, not these payload contracts.

`Scan` carries the source, generation, page cursor and last durably stored checkpoint. `Snapshot.ScanID` identifies one consistent generation, with no duplicate item carrying conflicting versions. A provider must use a service snapshot token or implement an equivalent complete scan/revalidation strategy. If it cannot prove coverage (permissions, rate limit, retention, truncation, failed pagination or changing dataset), it returns an error or an incomplete scan. An empty page is not itself completion. `Complete=true` is permitted only on the last page, with no next cursor, and certifies coverage of the entire configured source across all pages.

Core compares opaque item/version pairs; it never examines service payload fields. It stages incomplete generations separately from the authoritative previous snapshot. No absence is inferred and no authoritative snapshot is replaced until a generation is complete. A complete scan yields changed canonical Events and the IDs of observations now absent. Absence is a generic observation change, **not permission to delete or finish Work**. The runtime represents it as `core.ingress.absent` carrying source/item/last version with a delivery identity derived from the scan generation and item. The absence envelope preserves the last canonical observation’s correlation key and explicit Work ID when present, so it can reach the same objective even when item identity differs from correlation identity; it does not attribute the absence to an earlier Execution. Domain routes decide its significance. Where exact external deletion history matters, adapters expose a canonical tombstone observation/event instead; absence cannot invent the external deletion time. Tombstones remain discoverable for the provider's declared replay horizon.

Generation staging, checkpoint advancement, resulting Event acceptance and observation publication use B02 transactions/KV. Core may durably stage pages and their page cursors before completion, but incomplete staging cannot trigger absence. After a crash it resumes the saved generation if valid or discards only staging and starts a new one. Failed pages cannot advance a checkpoint. Generations are serialized per source/scope. Push events can be accepted during a scan but cannot rewrite its staged snapshot; subsequent reconcile resolves newer external state. Delivery dedup prevents duplicate Events from overlap. Reconcile is not a total order of external history and cannot recover transitions that the provider no longer exposes. 02-02 implements these rules and crash boundaries; the reference `ObservationSet` is only a pure diff oracle with caller-owned staging/checkpoint persistence.

## Executor lifecycle and continuity

`Run` starts one attempt and returns a `RunHandle`; `Wait` observes its structured `Result`. Four outcomes are valid: completed, failed, waiting and handoff. An executor transport/process error is distinct from a declared failed outcome, and neither silently completes Work. B02 defines persisted state mapping; runtime retry/wake decisions are 01-04. Shell exit status and agent result parsing must translate into this common surface. Usage has optional token counters and optional finite nonnegative cost with currency. Missing measurements stay absent, rather than becoming a false zero.

Capabilities advertise mechanical interrupt, inject, resume, workspace and exactly one toolbelt transport (`mcp`, `cli`, `sdk`, `none`). `ValidateBinding` rejects unavailable requirements, unknown transports and advertised controls lacking their optional Go interfaces before any execution is scheduled. An empty required transport means no transport constraint; `none` explicitly requires none. A reporting route must require its selected transport. An active inject/interrupt policy implies the corresponding capability, or an explicit fallback resolved in 01-04. No inferred fallback or semantic “coding ability” label exists.

Run context contains a scope configuration snapshot, resolved secrets for this execution, optional opaque resource descriptors, and the endpoint/token. No workspace is required. Resource acquisition, copy/setup and cleanup semantics stay in 03-02. Shell presents `OS_ENDPOINT`, `OS_TOKEN` and `os` on PATH; MCP and SDK present the same operations and authority. `none` receives no usable toolbelt credentials. Context secrets/tokens and resource internals must never enter logs or lifecycle attributes.

Executor continuity is private, keyed by Work ID, and must be separated by executor/connection namespace. The executor owns resume-versus-fresh, session identifiers and handoff economics. Core persists small opaque recovery metadata through the fenced `PersistRecovery` callback; this must succeed before acknowledging a launched handle. Executors must close any launch/persist crash window by recording intent before launch, using a deterministic discoverable handle, or cleaning up an unacknowledged launch. Large transcripts use artifacts. Callback failure cannot return successful launch acknowledgement.

`Recover` receives the same Work/Execution identity, executor-owned metadata and newly claimed authority. It adopts an existing detached attempt or returns its already finished result via a handle. Unknown/dead/unverifiable metadata returns `ErrNotAdoptable`. It **never launches a replacement** or interprets metadata in core. Core decides retry/failure after that result; new attempts use Run. The executor must replace old process credentials with the new token before allowing further mutations. Old credentials remain fenced even if an old process lives. Capability `resume` concerns continuing a parked wait; it is independent of detached adoption. `Resume` uses the accepted wake event as trigger, same attempt and new lease/token. A non-resuming wait terminates the attempt and wake creates N+1. Cancellation of `Wait` only cancels observation; explicit interruption/cancellation policy controls the process. The generic inject completion/consumption acknowledgement is deliberately deferred to 04-02: current success means accepted for delivery, and must not be treated as proof of consumption.

## Toolbelt authority and registration

`Toolbelt.Call(token, call)` is the one execution-facing surface. `TokenIssuer` and `Registrar` are trusted registration/runtime interfaces. Registrations declare in-process `ContractVersion=1`, never a storage-capability flag. This does not specify the stage-07 subprocess protocol. Registration is atomic: names and event types are declared before binding, duplicate owners and reserved builtin names fail without partial registration. Extension operations require a registered handler, an explicit token operation allowlist and their user-bound route/executor; registering an operation grants no privilege. Extension operation handlers receive validated authority and opaque input, never the raw token. Domain behavior stays in the handler. Any emitted Events must pass the same declared-family, authority and causation checks as builtin emit; no handler gets trusted control-plane authority by virtue of registration. Remote side effects run outside storage transactions, use adapter markers for ambiguous writes and reconcile their results. The reference double supports pure operation handlers only.

Tokens are unpredictable, per execution and lease epoch, bounded in lifetime, revocable and never logged/persisted as plaintext coordination payloads. Issue a fresh token after claim/recovery/resume. Expiry is exclusive. Validate scope, Work, Execution, operation allowlist, revocation and B02 lease on **every call including reads**; token validity alone is insufficient. Park, termination, cancellation, lease release/expiry or supersession invalidates access immediately. Optional request IDs are assertions narrowing the token's target; they cannot switch target. Tokens grant neither neighboring Work in the same scope nor another scope. Transport and local endpoint authentication details remain 01-05. No unauthenticated request becomes a nil storage Guard.

| Operation | Required behavior |
| --- | --- |
| `emit` | Only declared/allowed event types; preserve client idempotency delivery key; trusted execution source, Work, Execution and trigger causation; reject forged parents/targets and unowned correlations; commit before acknowledgement. Root Events cannot be submitted through execution authority. |
| `create_work` | Create child with current Work as immutable parent and current scope; reject foreign scope/parent and conflicting keys; preserve causation via an accompanying accepted `core.work.created` Event in the same transaction. IDs are allocated before commit for retry safety. |
| `wait` | Current Work/Execution only; B02 match/timeout registration and state/authority release are atomic; resume-capable executor parks, other executors end waiting. Event/wake race semantics and cross-work subscriptions are 01-04. |
| `declare_outcome` | Validate structured outcome; fence persistence and release attempt authority. Work completion/retry is runtime policy. Waiting requires the `wait` operation's predicate/timeout and cannot be declared without registration. |
| `read_context` | Return only accumulated context authorized for this Work; never neighboring Work, raw secrets, tokens or executor continuity metadata. |

Core derives causation from the current trusted trigger, never from client-selected roots. Child creation and timeout Events carry that ancestry. Emission does not bypass the core chain-depth/per-chain-rate controls defined in 01-04. Production implementations join all coordination changes in the fenced B02 transaction. Extension operations performing external writes must revalidate authority for each subsequent coordination mutation; a successful initial check cannot grant indefinitely valid authority.

## Required lifecycle telemetry

The required lifecycle hooks cover acceptance/dedup/rejection, reconcile start/page/complete/partial/failure, route/binding decisions (including drop), Work transitions, Execution queued/start/park/resume/outcome/cancel, lease renew/loss/recovery/adoption, wait register/wake/cancel, timer arm/fire/cancel and toolbelt calls/emissions/rejections. Every actual transition emits a record after its corresponding durable commit, with retries/duplicate exporter delivery identifiable; logs/metrics/traces must not imply a rolled-back transition happened. 02-08 defines buffering/replay and maps these hooks to OpenTelemetry.

Every record includes name, trusted timestamp, scope, causal Event and trace. Once associated with Work, include Work ID. Every `execution.*` record additionally requires Work/Execution IDs and executor binding. Related route/emission/wait/timer records retain these fields whenever an attempt exists. Before association those IDs are legitimately absent; the system must not fabricate them. An ingress scan or pre-acceptance rejection uses a trusted ingress/control trigger Event to anchor the trace. `From`/`To` describe generic lifecycle states; attributes explain route choice/reason and safe diagnostics. Runtime supplies correlation, never an executor's unverified payload. Recovery retains the original trace/attempt and records the new lease epoch; accepted wake/emission Events link the chain. High-cardinality IDs belong in logs/traces, not metric labels.

Executors report usage/cost on that same execution correlation; shared `Measurement` carries the optional counters and currency. Outcome quality and handoff experiments are extension metrics, with no core semantic interpretation. Opaque payloads, recovery state, request bodies, secret config and bearer tokens are excluded from telemetry. `Redact` copies attributes, filters sensitive keys and replaces known secret values before any exporter sees them. Identifiers/state names must be secret-free at their source; redaction cannot repair identities without breaking correlation. Errors must be sanitized before becoming attributes. Artifact streams need their own producer redaction policy.

The Observer contract is required even with no exporter configured. Exporters are optional and must support shutdown. Export failures produce safe diagnostics and cannot roll back durable transitions, stop scheduling or change execution outcomes. Local observability, buffering/drop accounting and exporter fault tests arrive in 02-08; passing the reference observer proves validation/redaction only, not OpenTelemetry coverage.

## Verification and follow-on decisions

Run `go test -race ./...`, `go vet ./...` and `go build ./...`. Shared ingress fixtures check declarations/loss, stable normalization, pagination and canonical overlap. Diff fixtures check incomplete scan safety, mixed generations, absence only on completion, unchanged snapshots and dedup against public storage. Executor fixtures cover every structured outcome, recovery metadata persistence failure, adoption without replacement and unknown metadata. Binding tests reject unsupported/misadvertised capabilities and transport mismatches. Toolbelt cases cover each builtin, custom operation, registration conflicts, allowlists, forged causation, cross-target authority, exact token expiry, revocation, lost lease and authority release after wait/outcome. Telemetry fixtures reject missing correlation and require redaction. Negative controls weaken canonical identity, loss declarations, toolbelt authority and telemetry validation and must fail the actual shared cases.

These are contract proofs against volatile synthetic doubles. Service transport correctness, process kill/restart, SQLite durability, actual secret transport and OTel instrumentation remain later tickets. 01-04 owns ordering, active-policy acknowledgements/fallbacks, wake races, causal bounds and retry/adoption policy; 01-05 owns configuration, secret resolution and local authentication; 01-06 closes the combined contracts gate. 04-02 refines generic injection acknowledgement against Slack evidence. Third-party schema evolution/manifest/transport remain stage 07.

B05 update: [configuration, secrets and local management](config-management.md) now specifies concrete inheritance/tombstones, pinned generations with current authorization ceilings, secret resolution and local HTTP-over-Unix-socket bearer authentication. Apply B05 wherever this document assigns decisions to 01-05; runtime enforcement remains 02-06.
