# Local backup bundles

Ticket 02-01 implements [backup composition](../../internal/backup/backup.go) alongside [SQLite and artifacts](sqlite-artifacts.md). Operator commands and recovery runbooks remain 06-02. These APIs do not start a daemon or transfer scope ownership.

`backup.Create(ctx, destination, database, artifacts, build)` requires a previously absent destination under an operator-controlled parent directory. It pins artifact deletion **before** taking a SQLite online snapshot, reads Execution references from that snapshot, copies every referenced artifact with streaming integrity checks, and writes a versioned manifest containing the database schema, build identity and SHA-256 digests. Missing content fails the backup; this first implementation does not omit expired references. No logs or artifact bytes enter coordination KV.

The bundle is built in a private sibling staging directory. Files and directories are flushed before rename; the parent is flushed after publication. Until publication, the destination is absent. A crash may leave a `.conduit-snapshot-*` directory: it is incomplete and must not be selected as a restore point. Remove abandoned staging directories only with no backup/restore operation running. A final directory-sync failure may leave a complete published destination with an ambiguous durability result; the API returns the error, and callers must inspect that destination before retrying. Bundle paths must not be shared by concurrent publishers.

`backup.Restore(ctx, bundle, destination, now)` requires a stopped, isolated, absent destination. It rejects unsupported/incomplete manifests, altered database bytes, altered artifact bytes and omitted or changed references from the captured database. It restores into a private staging directory, fences every backed-up lease while preserving its epoch, then publishes the complete state directory. A new Claim must advance that epoch; old execution credentials cannot commit. Failed validation publishes no destination. The resulting layout contains `conduit.db` and `artifacts/`; instance credentials/config are provisioned separately by later bootstrap work.

Digests detect corruption and incomplete copies; they do not authenticate a bundle against an adversary able to replace its manifest and all bytes. Keep bundles owner-only because snapshots contain private Work/Event/configuration and executor continuity. Backups require a compatible schema/build and an operator-controlled local filesystem supporting SQLite locking, atomic rename and directory sync. Power-loss guarantees depend on the filesystem and storage honoring flushes. Restore neither adopts a surviving external process nor authorizes a second scope owner; those remain runtime recovery responsibilities.

`go test -race ./internal/backup` exercises captured correlation/timer/history/content, exclusion of later live changes, lease fencing, existing-destination refusal, manifest/database/artifact corruption and missing-reference rejection. SQLite and artifact suites separately exercise process kill/reopen and transaction/publication fault boundaries.

06-02 adds the operator commands and runbooks ([recovery](recovery.md)). `open-conduit backup create DEST`, `backup verify BUNDLE` and `backup restore BUNDLE --to DIR` run offline under the state directory's daemon lock (`internal/bootstrap/state.go`). A restore also revokes the bundle's operator credential and writes a fresh `private/operator.token` through the locked local reset (`auth recover`). `backup.Inspect` reads a manifest without verifying its bytes. `TestDaemonMigrationRehearsal` restores a bundle and restarts on it with no repeated external write, claim or job run, and refuses a tampered bundle.
