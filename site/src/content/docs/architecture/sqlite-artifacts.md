This page describes the durable storage behind Open Conduit's [B02 storage contract](../domain-storage/). Coordination state lives in a SQLite database ([`internal/storage/sqlite`](https://github.com/open-conduit/open-conduit/tree/main/internal/storage/sqlite)) and large content lives in a separate file artifact store ([`internal/artifacts`](https://github.com/open-conduit/open-conduit/blob/main/internal/artifacts/files.go)). The public coordination and artifact interfaces remain separate. In the running daemon, the composition root in [`internal/bootstrap`](https://github.com/open-conduit/open-conduit/tree/main/internal/bootstrap) opens `conduit.db` and `artifacts/` under the state directory; these packages supply storage only, not event routing, execution scheduling, provider clients or scope ownership.

## Coordination backend

`sqlite.Open(ctx, path)` opens an independent Open Conduit database; `Close()` releases its connections. The backend uses the pure Go `modernc.org/sqlite` driver pinned to v1.38.2, preserving the Go 1.24.2 compatibility floor and Darwin/Linux amd64/arm64 targets. SQLite WAL mode and `synchronous=FULL` are required, not optional throughput flags. Each Store uses one pooled connection for `Transact`, and `BEGIN IMMEDIATE` serializes transaction admission across independently opened Store handles before callback evaluation. `View` reads through up to four more connections opened with `query_only`: each runs a deferred read transaction, which in WAL mode reads the snapshot committed when its first statement runs, alongside the writer and other Views. A callback is never transparently retried by the backend. A lock not taken within the 5 s busy timeout (SQLite's busy or locked) is `storage.ErrTransient`, having committed nothing, which `storage.Retry` reruns ([transactions](../domain-storage/#transactions-and-checkpoints)). A constraint failure is `storage.ErrConflict`. Every open runs SQLite's `quick_check` and the foreign key check and refuses a database that fails them. `quick_check` skips matching each index against its table, so it costs less than `integrity_check` as the database grows. `Store.IntegrityCheck` runs the full `integrity_check`; snapshot verification, restore and the stopped-state `database` check use it ([recovery](../recovery/)).

Indexed tables store the five primitive records, delivery identity, exclusive correlation ownership, processing checkpoints, timer revision tombstones and namespaced coordination KV. The database is not a serialized in-memory state blob. Revision/lease checks and event/KV/timer changes share the same transaction. A successful callback result is acknowledged only after commit; callback errors, panics and cancellation before commit roll back.

The persisted schema is version 1. Opening a newer schema fails without modifying it, and so does opening records a newer binary wrote (a higher `record_format`; [schema compatibility](../domain-storage/#artifacts-and-local-state-compatibility)); migrations are ordered and transactional and failure must preserve the prior schema and records. SQL data is coordination/history, not a place for transcripts or large binary artifacts.

SQLite is the `sqlite` [storage backend](../domain-storage/#backend-lifecycle) (`sqlite.Backend`, registered from the package's `init`), and `*sqlite.Store` is its `storage.Database`. A location must be an absolute path. `Open` and `Inspect` hold an exclusive `flock` on `<path>.lock` until `Close`, so a second owner gets `storage.ErrInUse`; `sqlite.Open` itself takes no lock, so tests and the snapshot reader can still open a file more than once. `Inspect` copies the database and its WAL into a private temporary directory and opens the copy, so nothing `Open` does (recovering the WAL, recording the record format) reaches the original; the copy goes on `Close`. `Snapshot` takes an online backup (below) and reads that copy. `Fence` clears every lease in one transaction.

`Store.Backup(ctx, destination)` requires a previously absent destination and uses SQLite's online backup API for a consistent standalone snapshot, including committed WAL data. Copying a live `.db` file directly is not a backup. `sqlite.Restore(ctx, snapshot, destination, now)` validates schema/integrity, requires a new isolated destination and fences retained lease authority before the restored database can be used. Restoration is a stopped-state operation; lease fencing alone does not stop old external processes or authorize two daemons to own the same external scope.

## Artifact publication and integrity

[`internal/artifacts`](https://github.com/open-conduit/open-conduit/blob/main/internal/artifacts/files.go) implements `storage.ArtifactStore`, and `artifacts.Backend` is the `files` [artifact backend](../domain-storage/#artifacts-and-local-state-compatibility), whose location is the store directory's absolute path. `artifacts.Open(root)` creates owner-only directories and takes an exclusive nonblocking filesystem lock on `.lock`; another process or Store handle cannot own the same artifact tree. The lock is the file store's own way of owning a local directory, not something the artifact contract needs. `Close()` aborts active writers and releases ownership. Lock lifetime includes backup pins. Directory ownership and modes are checked; symlink roots, object directories and content/metadata files are rejected. Artifact IDs are random 256-bit hex identifiers; caller paths never select a file.

The layout contains `pending/{id}/data` for unpublished streams and `objects/{prefix}/{id}/{data,meta.json}` for committed immutable objects, where `{prefix}` is the ID's first two hex characters. The fan-out lets a listing page read only the prefix directories it spans. A store opened with objects in the earlier flat layout (`objects/{id}`) has them moved under their prefix by `Open`, under the lock, one rename each, so an interrupted move is finished by the next open. A binary from before the fan-out can't read a moved store, and it can't open the record format 7 database beside it either, so rolling back is a restore from the bundle taken before the upgrade. Files are `0600`; directories are `0700`. Publication performs these steps:

1. Stream directly to a pending file while computing its length and SHA-256; no whole-file buffer or coordination KV is used.
2. On `Commit(ctx)`, flush and close content, write/fsync immutable reference (with its digest), hash and publication-time metadata, and fsync the staging directory.
3. Atomically rename the staging directory into `objects`, then fsync the objects and pending directories before returning the reference.

These guarantees rely on normal local filesystem rename/fsync semantics and functioning storage hardware; the tests do not simulate physical power failure. An acknowledged commit has flushed content and directory entries. Before acknowledgement, cancellation or any publication error yields no usable reference. Best-effort cleanup can leave an orphan after an interrupted/ambiguous filesystem operation, which is why retention cannot assume every object has a coordination reference. `Close` without Commit aborts; repeated commit, close or write-after-close returns `ErrClosed`.

`Open(ctx, ref)` checks the exact reference metadata and content length, then streams while verifying SHA-256 at EOF. An object published before references carried digests has its digest only in `meta.json`'s `SHA256`; the store reads it as the reference's, so a reference with or without the digest opens it. Full consumers and backup copies must read to EOF and check the final read/copy error; closing a partially read reader is not an integrity check. Missing/retained-away content returns `storage.ErrNotFound`; same-size corruption returns `artifacts.ErrCorrupt`. Content loss does not rewrite or invalidate coordination history. The artifact store does not implement producer redaction: executors must redact before publication as required by B03/B05.

## Recovery and retention

After process death, opening the store again recovers it: once `Open` holds the lock, which proves no other process still owns them, it removes unpublished pending directories and preserves all committed objects. `List(ctx, after, limit)` lists only committed objects. It starts at the cursor's prefix directory and stops at the end of the page, so a page reads the prefix directories it spans, each about 1/256 of the store, never the whole store; a full walk of N objects in pages of 1000 reads each prefix directory about N/256000 + 1 times. A SIGKILL after successful Commit preserves readable content on reopen; a SIGKILL while streaming exposes no reference/content and the pending bytes are cleaned on recovery.

`Collect(ctx, before, liveIDs)` removes only committed objects published before `before` that are absent from the supplied protected set, plus aged stale pending streams. Active writers are always preserved. The caller must supply a complete reference set and coordinate against attaching an old orphan during collection. Runtime retention policy must first release references or explicitly record their expiration; this backend cannot infer the live set from a partial database scan. Metadata/history remains in SQLite after content deletion. `Delete(ctx, ref)` is idempotent and checks reference identity before removing content.

In the daemon, artifact retention is the scheduler's `kept_executions` sweep, which records each expiration first and then removes that attempt's content through `Delete` ([retention](../observability-history/#retention)). The daemon opens the store once at start, after the state lock and before the scheduler runs, so pending streams a killed process left are removed. On every retention pass it then calls `Collect` with every artifact any execution references, each of its turns' (`domain.Execution.AllArtifacts`), as the live set and a 24-hour grace (`Options.ArtifactGrace`). Executors attach what they publish in the same result, so the grace far exceeds the publish-to-attach window; content still unattached after it is an orphan. A collection error (for example an object with corrupt metadata) stops that pass and is logged as an `artifacts` runtime diagnostic.

## Complete backup bundles

[`internal/backup`](https://github.com/open-conduit/open-conduit/tree/main/internal/backup) composes the backend's snapshot and artifacts with a versioned, complete manifest. Its `Create` operation acquires an artifact `Pin()` **before** the database snapshot, enumerates references from that exact snapshot (`Database.Snapshot`'s read), copies them through `Pinned.Open` with streaming integrity checks, and publishes the manifest only after all required copies are durable. A pin holds retention/deletion until closed; use `Pinned.Open`, not nested `Store.Open`, while pinned. Concurrent producers can publish new objects, but they are outside the captured database reference set. References of retention-expired Executions are recorded in the manifest as omitted rather than copied; any other missing referenced content fails the backup rather than silently claiming a complete restore point.

`Store.Import(ctx, ref, reader)` restores an immutable reference ID and metadata in a new artifact store, streaming bytes and requiring exact length, the reference's digest when it has one, and successful source EOF. Root backup composition additionally verifies SHA-256 against the bundle manifest, and refuses a manifest whose reference names a digest other than the one it records for the bytes. A failed/partial copy is unpublished. Restore uses new isolated destinations, validates manifest/schema/content and fences the backend's leases before exposing a completed state directory. Partial staging directories are not restore points. The operator commands built on these APIs are described in [backup bundles](../backup-bundles/) and [recovery](../recovery/).

## Evidence

The unchanged shared storage suite and the lifecycle suite run against SQLite, with seven weakened SQLite backends as the lifecycle suite's negative controls ([evidence](../domain-storage/#evidence)). Backend tests cover reopen, competing connections, migration failure/newer schema refusal, callback error/panic/cancellation rollback, process death at transaction boundaries and backup restoration of correlation ownership/pending timers. The deliberately weakened reference controls continue to fail their selected shared cases.

The file store runs the shared artifact suite (`conformance.RunArtifacts`) with seven weakened file stores as its negative controls ([evidence](../domain-storage/#evidence)). Artifact tests exercise normal publication/abort/reopen, streaming concurrency, injected data-flush/publication/directory-flush failures, cancellation, same-size corruption, reference/path/permission checks, directory ownership, retention/live-set protection and a pinned copy racing deletion. Subprocess tests synchronize with a pipe and SIGKILL immediately before or after Commit, then reopen/recover. They do not use elapsed sleeps as correctness barriers. [`TestDaemonArtifactCleanup`](https://github.com/open-conduit/open-conduit/blob/main/integration/daemon_artifacts_test.go) SIGKILLs the real daemon, leaves an unfinished pending stream and unreferenced objects in its artifact store, and restarts it: the stream is gone once the daemon is ready, the aged orphan goes on the first retention pass, and a backdated referenced object and a recent orphan stay. There is no filesystem or device power-loss testing.
