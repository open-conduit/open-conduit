This page records decision B03: the public Go contracts that extensions and executors implement and that the core relies on, covering ingress, route handlers, executors, the execution toolbelt and lifecycle telemetry. The contracts live in [extension](https://github.com/open-conduit/open-conduit/blob/main/extension/ingress.go) and [observability](https://github.com/open-conduit/open-conduit/blob/main/observability/observability.go). [Shared conformance cases](https://github.com/open-conduit/open-conduit/blob/main/conformance/extensions.go) run against [volatile reference doubles](https://github.com/open-conduit/open-conduit/tree/main/conformance/reference) and against the real ingresses, executors, toolbelt and telemetry pipeline. These contracts supplement [B02](../domain-storage/). They are in-process Go contracts; the [extension subprocess protocol](../extension-protocol/) (B08) carries them over the wire.

Observability is a **required fifth cross-cutting contract**, alongside ingress, executor, toolbelt and storage. It is not a sixth primitive. The contract defines the correlation and reporting boundary without an SDK dependency; the OpenTelemetry mapping and export pipeline live in `internal/telemetry` ([lifecycle telemetry, run history and doctor](../observability-history/)).

## Ingress identity, observations and recovery

An ingress implements both `Push` and `Reconcile`, even if its only family is explicitly non-re-derivable (in that case reconcile may return an empty complete snapshot). Its registration declares each event family as recoverable or gives a concrete loss limitation. An arbitrary one-shot POST without readable backing history is not recoverable; the schedule extension's custom webhook family `schedule.webhook` is declared one-shot with a loss limitation for that reason, and its reconcile returns an empty complete snapshot. Each recoverable family (for example GitHub push, release and workflow-run) must establish its own readable history, permissions, retention and recovery horizon; a service-wide recoverability claim is insufficient.

`Source.Namespace` is a stable configured account/resource namespace. Scope is supplied by trusted configuration. Account identifiers, not credentials, determine identity; changing credentials cannot generate new logical events. Two scopes watching the same external source must coordinate ownership rather than silently duplicate it by changing its identity. B02 correlation ownership remains global within that namespace.

An observation contains an opaque item ID, an equality-only version token and its canonical Event. Adapters normalize payloads, timestamps, event family and canonical `(source, delivery_id)` identically for push and reconcile. The version must distinguish recurring transitions such as A → B → A; a content hash alone cannot identify both occurrences. Occurrence time is external time; receipt time reflects actual receipt and need not be identical across real transports. Internal Event ID/receipt time are not dedup identity: B02 returns the first accepted envelope on overlap. Multiple distinct events in one delivery get distinct stable delivery IDs (for example delivery/item/change); thread correlation never serves as event identity.

Recoverable push deliveries yield observations. Non-re-derivable families yield direct Events and explicitly disclose what is lost before acceptance. All emitted families must be declared. Push normalization and reconciliation perform no coordination writes. Their return values do not acknowledge acceptance: core validates the envelope and declarations, accepts durably, and only then acknowledges the delivery. Transport authentication and HTTP response mapping belong to service implementations, not these payload contracts.

`Scan` carries the source, generation, page cursor and last durably stored checkpoint. `Snapshot.ScanID` identifies one consistent generation, with no duplicate item carrying conflicting versions. A provider must use a service snapshot token or implement an equivalent complete scan/revalidation strategy. If it cannot prove coverage (permissions, rate limit, retention, truncation, failed pagination or changing dataset), it returns an error or an incomplete scan. An empty page is not itself completion. `Complete=true` is permitted only on the last page, with no next cursor, and certifies coverage of the entire configured source across all pages.

Core compares opaque item/version pairs; it never examines service payload fields. It stages incomplete generations separately from the authoritative previous snapshot. No absence is inferred and no authoritative snapshot is replaced until a generation is complete. A complete scan yields changed canonical Events and the IDs of observations now absent. Absence is a generic observation change, **not permission to delete or finish Work**. The runtime represents it as `core.ingress.absent` carrying source/item/last version with a delivery identity derived from the scan generation and item. The absence envelope preserves the last canonical observation’s correlation key and explicit Work ID when present, so it can reach the same objective even when item identity differs from correlation identity; it does not attribute the absence to an earlier Execution. Domain routes decide its significance. Where exact external deletion history matters, adapters expose a canonical tombstone observation/event instead; absence cannot invent the external deletion time. Tombstones remain discoverable for the provider's declared replay horizon.

Generation staging, checkpoint advancement, resulting Event acceptance and observation publication use B02 transactions/KV. Core may durably stage pages and their page cursors before completion, but incomplete staging cannot trigger absence. After a crash it resumes the saved generation if valid or discards only staging and starts a new one. Failed pages cannot advance a checkpoint. Generations are serialized per source/scope. Push events can be accepted during a scan but cannot rewrite its staged snapshot; subsequent reconcile resolves newer external state. Delivery dedup prevents duplicate Events from overlap. Reconcile is not a total order of external history and cannot recover transitions that the provider no longer exposes. The runtime implements these rules and crash boundaries ([event ingress](../event-ingress/)); the reference `ObservationSet` is only a pure diff oracle with caller-owned staging/checkpoint persistence.

### Adapter rules from the real ingresses

The [GitHub extension](../github-extension/) and the [Slack extension](../slack-extension/) settle these points for every adapter:

- An adapter may derive the version from the whole normalized envelope, as long as occurrence-bearing content distinguishes lifecycle recurrences (for GitHub, `closed_at` and the reopen generation). Attribute-only recurrences and the adapter's own projection writes are then deliberately not separate observations.
- The runtime publishes a generation's changes in lexical item order, so adapters nest dependent items (comments) under the item that may create Work.
- Transport authentication wraps header-borne delivery metadata into the Delivery body at the webhook boundary; the payload contract is unchanged.
- A push transport whose authenticated connection, not a signature, is the transport-authentication boundary (Slack Socket Mode) acknowledges envelopes only after durable acceptance, exactly as an HTTP status is.
- A non-re-derivable family that never accompanies an observation in one delivery (Slack's push-only deletions) is tested through the optional `OneShot` delivery of `conformance.IngressFixture`: the canonical delivery must then yield exactly the canonical observation and no direct Event, and the one-shot family is checked from `OneShot`.

## Executor lifecycle and continuity

`Run` starts one attempt and returns a `RunHandle`; `Wait` observes its structured `Result`. Four outcomes are valid: completed, failed, waiting and handoff. An executor transport/process error is distinct from a declared failed outcome, and neither silently completes Work. B02 defines persisted state mapping; runtime retry/wake decisions are [B04](../runtime-semantics/). Shell exit status and agent result parsing must translate into this common surface. Usage has optional token counters and optional finite nonnegative cost with currency. Missing measurements stay absent, rather than becoming a false zero.

`RunRequest.Inputs` is the acceptance-ordered batch presented to this attempt, including ordinary context before a wake. `Trigger` remains the selected event (the wake winner on Resume); recovery restores the same durable batch. Immutable `Execution.TriggerID` records the original attempt trigger. Runtime retains separate causal continuation ancestry when a parked attempt resumes.

Executor errors may implement the optional public `RetryHintProvider`, returning `RetryHint{ResetAt}`. Executors can implement it using `extension` alone. A nil reset means unknown; core validates the timestamp, applies generic backoff and retains a bounded failure budget. The callback runs outside coordination transactions. Provider-specific classification and error text stay in the executor. A structured *failed* result can also carry a hint in `extension.Result.RetryHint` (for example a usage limit's reset). Core applies it like a `RetryHintProvider` error, but the observed result also establishes that the attempt finished, so no uncertain hold remains. `ValidateResult` rejects a hint on any other outcome.

`extension.Result.Workspace` (`WorkspaceRecord`: kind, lease reference, directory, summary, description) lets every executor report the resource it ran in for history, and `extension.Resource.Summary` is a provider's one-line description of it. `domain.Binding.TimeoutSeconds` carries a binding's deadline.

Capabilities advertise mechanical interrupt, inject, resume, workspace and exactly one toolbelt transport (`mcp`, `cli`, `sdk`, `none`). `ValidateBinding` rejects unavailable requirements, unknown transports and advertised controls lacking their optional Go interfaces before any execution is scheduled. An empty required transport means no transport constraint; `none` explicitly requires none. A reporting route must require its selected transport. An active inject/interrupt policy implies the corresponding capability, or an explicit fallback ([B04](../runtime-semantics/#active-event-policies-and-acknowledgements)). No inferred fallback or semantic “coding ability” label exists.

Run context contains a scope configuration snapshot, resolved secrets for this execution, an optional host-bound `ResourceBroker` (nil without a binding resource), and the endpoint/token. No workspace is required. Resource acquisition, copy/setup and cleanup semantics are [B07](../workspaces/): the public `ResourceProvider` contract gives idempotent per-owner acquisition recorded before creation, `Lookup` without creation, and host-driven `Reconcile` from durable owner state (terminal plus confirmed exclusion). Core only passes the host-bound broker through `SchedulerOptions.Resources`. Shell presents `OS_ENDPOINT`, `OS_TOKEN` and `os` on PATH; MCP and SDK present the same operations and authority. `none` receives no usable toolbelt credentials. Context secrets/tokens and resource internals must never enter logs or lifecycle attributes.

Executor continuity is private, keyed by Work ID, and must be separated by executor/connection namespace. The executor owns resume-versus-fresh, session identifiers and handoff economics. Core persists small opaque recovery metadata through the fenced `PersistRecovery` callback; this must succeed before acknowledging a launched handle. Executors must close any launch/persist crash window by recording intent before launch, using a deterministic discoverable handle, or cleaning up an unacknowledged launch. Large transcripts use artifacts. Callback failure cannot return successful launch acknowledgement.

`Recover` receives the same Work/Execution identity, executor-owned metadata and newly claimed authority. It adopts an existing detached attempt or returns its already finished result via a handle. Unknown/dead/unverifiable metadata returns `ErrNotAdoptable`. It **never launches a replacement** or interprets metadata in core. Core decides retry/failure after that result; new attempts use Run. The executor must replace old process credentials with the new token before allowing further mutations. Re-acknowledging identical metadata under the new lease is permitted; replacement metadata is rejected. Old credentials remain fenced even if an old process lives. Capability `resume` concerns continuing a parked wait; it is independent of detached adoption. `Resume` uses the accepted wake event as trigger, same attempt and new lease/token. A non-resuming wait terminates the attempt and wake creates N+1. Cancellation of `Wait` only cancels observation; explicit interruption/cancellation policy controls the process.

`InjectExecutor` has three answers: `nil` (accepted for delivery), `extension.ErrNotAccepting` (definitely not delivered) and any other error (ambiguous). `Inject` success means accepted for delivery and must not be treated as proof of consumption. A finished result carries consumption proof in `Result.ConsumedInputs` (the Events the running process demonstrably took in) on every outcome. When the result is recorded, core consumes each named input only if it holds an accepted inject intent for that execution and the input is still pending; other IDs are ignored, so the field grants no authority. Acknowledgement and completion races are settled in [generic inject acknowledgement](../runtime-semantics/#generic-inject-acknowledgement), and the shared executor suite checks them with `CheckInjectExecutor`.

Two further optional executor interfaces are public: `StopExecutor` (physical-stop evidence before `ConfirmStopped`) and `AttachExecutor` with `AttachSpec` and `ErrNothingToAttach` (the operator attach control; the management wire code is `nothing_to_attach`).

## Toolbelt authority and registration

`Toolbelt.Call(token, call)` is the one execution-facing surface. `TokenIssuer` and `Registrar` are trusted registration/runtime interfaces. Registrations declare in-process `ContractVersion=1`, never a storage-capability flag; `protocol.Version` versions the subprocess wire separately. Registration is atomic: names and event types are declared before binding, duplicate owners and reserved builtin names fail without partial registration. Extension operations require a registered handler, an explicit token operation allowlist and their user-bound route/executor; registering an operation grants no privilege. Extension operation handlers receive validated authority and opaque input, never the raw token. Domain behavior stays in the handler. Any emitted Events must pass the same declared-family, authority and causation checks as builtin emit; no handler gets trusted control-plane authority by virtue of registration. Remote side effects run outside storage transactions, use adapter markers for ambiguous writes and reconcile their results. The reference double supports pure operation handlers only.

Tokens are unpredictable, per execution and lease epoch, bounded in lifetime, revocable and never logged/persisted as plaintext coordination payloads. Issue a fresh token after claim/recovery/resume. Expiry is exclusive. Validate scope, Work, Execution, operation allowlist, revocation and B02 lease on **every call including reads**; token validity alone is insufficient. Park, termination, cancellation, lease release/expiry or supersession invalidates access immediately. Optional request IDs are assertions narrowing the token's target; they cannot switch target. Tokens grant neither neighboring Work in the same scope nor another scope. Transport and local endpoint authentication are [B05](../config-management/#local-transport-discovery-and-authority). No unauthenticated request becomes a nil storage Guard.

| Operation | Required behavior |
| --- | --- |
| `emit` | Only declared/allowed event types; preserve client idempotency delivery key; trusted execution source, Work, Execution and trigger causation; reject forged parents/targets and unowned correlations; commit before acknowledgement. Root Events cannot be submitted through execution authority. |
| `create_work` | Create child with current Work as immutable parent and current scope; reject foreign scope/parent and conflicting keys; preserve causation via an accompanying accepted `core.work.created` Event in the same transaction. IDs are allocated before commit for retry safety. |
| `wait` | Current Work/Execution only; B02 match/timeout registration and state/authority release are atomic; resume-capable executor parks, other executors end waiting. Event/wake race semantics and cross-work subscriptions are [B04](../runtime-semantics/#wait-registration-observation-and-exactly-one-wake). |
| `declare_outcome` | Validate structured outcome; fence persistence and release attempt authority. Work completion/retry is runtime policy. Waiting requires the `wait` operation's predicate/timeout and cannot be declared without registration. |
| `read_context` | Return only accumulated context authorized for this Work; never neighboring Work, raw secrets, tokens or executor continuity metadata. |

The production toolbelt ([toolbelt authority and local management](../toolbelt-management/)) records `wait`/`declare_outcome` as fenced per-epoch declarations that release toolbelt authority immediately. The predicate/timeout registration or outcome is applied when the trusted host observes the segment finish or suspend, because a client request alone is not exclusion proof. The declared exclusive watermark ensures registration backscans everything accepted in between.

The [shell executor](../shell-executor/) presents this surface as `OS_ENDPOINT`/`OS_TOKEN` (plus a replaceable `OS_TOKEN_FILE`) and the `os` CLI. The [Claude Code executor](../claude-code-executor/) is an `mcp` toolbelt executor: `os mcp` presents the same five builtins plus `call` over MCP stdio, through the CLI's authority path, with a replaceable credential file. Its session, resume-versus-fresh, handoff note, attachment and the handoff experiment are executor-private continuity in namespaced KV, keyed by Work ID.

Core derives causation from the current trusted trigger, never from client-selected roots. Child creation and timeout Events carry that ancestry. Emission does not bypass the core chain-depth/per-chain-rate controls ([B04](../runtime-semantics/#causal-bounds-and-rejection-evidence)). Production implementations join all coordination changes in the fenced B02 transaction. Extension operations performing external writes must revalidate authority for each subsequent coordination mutation; a successful initial check cannot grant indefinitely valid authority.

### Extension operation surface

Extensions extend the toolbelt through extension-neutral contract pieces; none adds a domain type ([engineering tools, waits and playbooks](../engineering-tools/)):

- `Operation.Wait`: an operation whose handler returns a `WaitPlan`, declared like the builtin wait. `Dependency` is a B04 dependency subscription with an opaque filter and `FromNow`, and `Registration.DependencyFilter` is a pure filter core evaluates inside the reconcile transaction.
- `CallRequestID(ctx)`: the caller's request identity for stable intent IDs.
- `OperationError`: a handler-authored safe refusal (code plus message) returned verbatim instead of a generic failure.

The reference toolbelt double supports pure handlers only.

### Translated emissions

`extension.Operation.Emit` is a **translated emission**, set instead of `Handler` or `Wait`. The handler returns an `EmitPlan`: an Event giving only type, delivery identity, optional occurrence time, key and data, plus a pure `Commit` callback. The toolbelt accepts that Event exactly like the builtin `emit`:

- a family the same registration declared, which the token allows;
- trusted `execution/<id>` source and trigger causation;
- `AcceptDerivedInTx` chain-depth and per-chain rate limits.

In the same transaction it writes the commit's `Record`s, which must stay in namespaces equal to the registration name or under `name.`, and only when the Event is newly added. It returns the commit's output (`Emitted` carries the accepted Event and its root and depth). A key the current Work does not own must lie in the registration's own source namespace (`name` or `name/…`). The Event is then addressed to that key rather than to the emitting Work, so the registration's own route can give it Work, while source and causation still record the emitter. Presetting identity, source, causation or target is refused, and nothing a refused plan names is committed. The issue-reporting extension uses it; see [issue reporting](../issue-reporting/).

**Cited causation.** `EmitPlan.Cause` may name an accepted Event the emission derives from instead of the attempt's trigger. The cited Event must be in the emitting Work's scope and have a key in the registration's own source namespace; anything else, a missing Event included, is refused (`ErrUnauthorized`). The new Event's causation is the cause and it joins the cause's chain. Its depth is one more than the deeper of the cause and the trigger, checked against the stricter limit, and it is charged to both chains' per-minute budgets. Citing therefore never shortens a chain or escapes the trigger's limits ([runtime semantics](../runtime-semantics/#cited-causation)). The introspection extension's fix request uses it to cite the report it fixes, so a fix traces through causation to the report and its origin ([introspection](../issue-reporting/#fix-work-and-cited-causation)).

## Route handlers

`RouteInput.Route` carries the route being evaluated, including its opaque handler config, so one handler can serve several routes (one per binding). `config.Registry.HandlerConfig` lets a registered handler validate that config at load/apply time. The [schedule extension](../schedule-extension/) uses both; it also derives `schedule.run.*` Events for `job:` waits, which GitHub's `ToolsOptions.Jobs` resolves without importing it.

## Setup hook

The optional [`extension.Setup`](https://github.com/open-conduit/open-conduit/blob/main/extension/setup.go) hook lets an extension own its setup. `SetupInfo` names a type and `Setup(ctx, SetupHost, args)` returns connections plus one scope. Core `open-conduit init <type>` hosts it with prompts, a browser opener, the secret store, a helper-command runner, offline validation and the merge, and it never interprets service details. GitHub (`init github`) and Slack (`init slack`) implement it; see [operator setup](../operator-setup/#extension-owned-setup).

## Required lifecycle telemetry

The required lifecycle hooks cover acceptance/dedup/rejection, reconcile start/page/complete/partial/failure, route/binding decisions (including drop), Work transitions, Execution queued/start/park/resume/outcome/cancel, lease renew/loss/recovery/adoption, wait register/wake/cancel, timer arm/fire/cancel and toolbelt calls/emissions/rejections. Every actual transition emits a record after its corresponding durable commit, with retries/duplicate exporter delivery identifiable; logs/metrics/traces must not imply a rolled-back transition happened. The runtime instruments every committed transition from the durable writes themselves and exports through a non-blocking, drop-accounted pipeline with an OpenTelemetry mapping ([lifecycle telemetry, run history and doctor](../observability-history/)).

Every record includes name, trusted timestamp, scope, causal Event and trace. Once associated with Work, include Work ID. Every `execution.*` record additionally requires Work/Execution IDs and executor binding. Related route/emission/wait/timer records retain these fields whenever an attempt exists. Before association those IDs are legitimately absent; the system must not fabricate them. An ingress scan or pre-acceptance rejection uses a trusted ingress/control trigger Event to anchor the trace. Host-polled ingress scan records (`ingress.` prefix) have no trigger Event, so they are anchored by their source attribute and a scan-derived trace; `Validate` accepts that anchor only for these records. `From`/`To` describe generic lifecycle states; attributes explain route choice/reason and safe diagnostics. Runtime supplies correlation, never an executor's unverified payload. Recovery retains the original trace/attempt and records the new lease epoch; accepted wake/emission Events link the chain. High-cardinality IDs belong in logs/traces, not metric labels.

Executors report usage/cost on that same execution correlation; shared `Measurement` carries the optional counters and currency. Outcome quality and handoff experiments are extension metrics, with no core semantic interpretation. Opaque payloads, recovery state, request bodies, secret config and bearer tokens are excluded from telemetry. `Redact` copies attributes, filters sensitive keys and replaces known secret values before any exporter sees them. Identifiers/state names must be secret-free at their source; redaction cannot repair identities without breaking correlation. Errors must be sanitized before becoming attributes. Artifact streams need their own producer redaction policy.

The Observer contract is required even with no exporter configured. Exporters are optional and must support shutdown. Export failures produce safe diagnostics and cannot roll back durable transitions, stop scheduling or change execution outcomes. Passing the reference observer proves validation/redaction only, not OpenTelemetry coverage; the export pipeline has its own buffering, drop accounting and exporter fault tests.

## Subprocess extensions

External extensions run behind `internal/extproc`, which adapts a supervised process back onto these same contracts ([runtime, trust model and schema evolution](../extension-protocol/#runtime-trust-model-and-schema-evolution)). The [extension subprocess protocol](../extension-protocol/) (B08, provisional) is JSON-RPC 2.0 over stdio, with a validated manifest declaring mechanical capabilities and mandatory namespaced KV, and a method catalogue in package [`protocol`](https://github.com/open-conduit/open-conduit/blob/main/protocol/methods.go) that maps every wire method to the contract it carries and its first-party users. In-process `ContractVersion` and wire `protocol.Version` are versioned separately.

First-party extensions running inside the daemon implement the in-process contract in [`extension/inproc`](https://github.com/open-conduit/open-conduit/blob/main/extension/inproc/inproc.go). Each surface is an optional interface: config types and validators, toolbelt operations, route handlers, start and stop, `Configure` with the same `protocol.ConfigureParams` an installed package receives, toolbelt registration, action providers, annotations, rendering of its own Event families, paced background tasks, doctor checks, playbooks, a telemetry exporter and a telemetry-event sink. The host gives each one its store, clock, logger, diagnostics and secrets, scoped to its own entries and connections as for an installed package (B05). Bootstrap holds one list of these extensions and composes every surface by iterating it. `human` and `posthog` are on the contract; the rest move over one at a time (issue #66).

Installed extension packages are loaded by the daemon and registered next to the first-party extensions through these contracts, with no domain branch in core. The first-party Slack extension and shell executor also run as subprocess packages (`packages/slack`, `packages/shell`) and pass the public certification runner, while staying registered in-process. See [extension packaging, SDK and certification](../extension-packaging/) (provisional).

## Evidence

Run `go test -race ./...`, `go vet ./...` and `go build ./...`. Shared ingress fixtures check declarations/loss, stable normalization, pagination and canonical overlap; they use synthetic state-change and one-shot families, with identical timestamps to check deterministic normalization, and run against the GitHub, Slack, Linear, Jira and Bitbucket ingresses. Diff fixtures check incomplete scan safety, mixed generations, absence only on completion, unchanged snapshots and dedup against public storage. Executor fixtures cover every structured outcome, recovery metadata persistence failure, adoption without replacement and unknown metadata. Binding tests reject unsupported/misadvertised capabilities and transport mismatches. Toolbelt cases cover each builtin, custom operation, registration conflicts, allowlists, forged causation, cross-target authority, exact token expiry, revocation, lost lease and authority release after wait/outcome; they also run against the production toolbelt. Telemetry fixtures reject missing correlation and require redaction, and run against the export pipeline. Negative controls weaken canonical identity, loss declarations, toolbelt authority and telemetry validation and must fail the actual shared cases.

The shared ingress, executor, inject and toolbelt cases also run unchanged against the example external extension and executor, both in-process and as subprocesses. The shared suite `conformance.RunExtensionKV` covers the namespaced KV reached through the host: own namespaces only, version tokens, atomic precondition batches and prefix order.
