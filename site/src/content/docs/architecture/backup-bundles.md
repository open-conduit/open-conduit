---
title: "Local backup bundles"
description: "How Open Conduit captures, verifies and restores a complete local backup of its state directory."
---

A backup bundle is a complete, self-verifying copy of the coordination database and the artifacts it references. [`internal/backup`](https://github.com/open-conduit/open-conduit/blob/main/internal/backup/backup.go) builds and restores bundles over the [storage backend lifecycle](../domain-storage/#backend-lifecycle) and the [artifact store](../sqlite-artifacts/); it never names a backend. The operator commands `open-conduit backup create`, `backup verify` and `backup restore` wrap it in [`internal/bootstrap/state.go`](https://github.com/open-conduit/open-conduit/blob/main/internal/bootstrap/state.go), and the [recovery](../recovery/) page holds the runbooks. The backup package itself never starts a daemon or transfers scope ownership.

## Creating a bundle

`backup.Create(ctx, destination, key, backend, database, artifacts, build, retention)` requires a previously absent destination under an operator-controlled parent directory. `artifacts` is the live `storage.ArtifactStore`, of any backend. Create commits a retention hold (`retention.Hold`, the runtime's `HoldRetention`) **before** taking the database's snapshot (`Database.Snapshot`), renews it every third of `HoldFor` (default 15 minutes, or whenever `Renewals` fires) while it copies, and releases it when done, published or not ([retention](../observability-history/#retention)). The hold's expiry is set on `retention.Now`, which must be the clock the retention sweep checks it against: the daemon passes its own clock, the scheduler's, and the offline command the wall clock. A renewal that fails stops the copy, since the hold could then lapse under it, and a backup without a hold is refused. It reads Execution references from that snapshot's own state, copies every referenced artifact with streaming integrity checks, and writes a versioned manifest containing the backend's name (omitted for SQLite, which older binaries assume), the database schema, build identity and SHA-256 digests. The snapshot is `conduit.db` in the bundle whatever the backend. References of Executions whose [retention](../observability-history/#retention) has expired are not copied: the manifest lists them under `Omitted`, since the sweep may already have deleted their content. The runtime owns the retention ledger, so the caller passes the lookup and the hold in `retention` (`internal/bootstrap` wires `runtime.RetentionInTx`, `HoldRetention` and `ReleaseRetention`); a nil `Expired` treats nothing as expired. Any other missing content fails the backup, which publishes nothing. The bundle's own `artifacts/` is a file store whatever the live backend, since it is part of the bundle format. No logs or artifact bytes enter coordination KV.

The bundle is built in a private sibling staging directory. Files and directories are flushed before rename; the parent is flushed after publication. Until publication, the destination is absent. A crash may leave a `.conduit-snapshot-*` directory: it is incomplete and must not be selected as a restore point. Remove abandoned staging directories only with no backup/restore operation running. A final directory-sync failure may leave a complete published destination with an ambiguous durability result; the API returns the error, and callers must inspect that destination before retrying. Bundle paths must not be shared by concurrent publishers.

## Restoring a bundle

`backup.Restore(ctx, bundle, destination, trust, now, expired, backends, target, record)` first applies `trust` to the manifest bytes it goes on to use ([signing](#signing-and-trust)), then imports the bundle's artifacts into the store `target` names: an artifact backend and a location, or, with no location, the backend opened at the staged directory's `artifacts` (bootstrap passes the file store, `artifacts.Backend`, unless the operator names another). The store must be empty: one that already holds content is refused, so a restore never mixes a bundle into a live store. When the location is outside the directory and the restore fails before the directory is published, what it imported there is deleted again; once it is published, its `storage.json` names that store, so a later failure (syncing the parent directory) leaves the content in place. A store inside the directory goes with the staged directory. `backup verify` always restores into the file store in its own temporary directory. Each is checked against its reference's digest; a reference recorded before references carried one is checked against the digest the manifest records. It looks up the manifest's backend through `backends` (the daemon passes `storage.LookupBackend`; a backend not built into the binary refuses the bundle). `record` writes into the staged directory before it is published (bootstrap's `storage.json` for a non-default backend), so a failure there publishes nothing. It requires a stopped, isolated, absent destination. It rejects unsupported/incomplete manifests, altered database bytes, altered artifact bytes and omitted or changed references from the captured database. A reference listed as omitted is accepted only on an Execution the restored retention ledger records as expired. It restores into a private staging directory with the backend's `Restore`, which fences every backed-up lease while preserving its epoch, then publishes the complete state directory. A new Claim must advance that epoch; old execution credentials cannot commit. Failed validation publishes no destination. The resulting layout contains `conduit.db` and, for the default artifact store, `artifacts/`; `record` adds `storage.json` naming the backend when it is not SQLite and the artifact backend when the operator chose one. The database carries every committed config generation (`core.config`), normalized and self-contained, so the restored directory starts from the generation the bundle was taken on without a config file ([config management](../config-management/)). Secret values, installed packages and extensions' private state directories are not part of the bundle ([recovery](../recovery/#backup-restore-and-credential-recovery)); the operator command writes a fresh operator credential (below).

## Signing and trust

The manifest holds the digest of the database and of every artifact, so an Ed25519 signature over its exact bytes authenticates the whole bundle ([`internal/backup/sign.go`](https://github.com/open-conduit/open-conduit/blob/main/internal/backup/sign.go)). Restore acts only on the bytes it checked, so a bundle changed during a restore gains nothing: it parses the manifest bytes the signature covers, reads the database once into a private copy hashed as it is written and restores that copy (which needs room for one more copy of the database beside the destination), and imports each artifact through a check on the stream it writes. The signature is a separate `manifest.sig`, so a binary from before signing still reads a signed bundle.

`open-conduit backup keygen FILE` writes a private key to an absent owner-only file and prints the public key. The operator stores the private key behind a secret reference outside the state directory and sets `settings.backup.signing_key` to that reference and `settings.backup.trust_keys` to the public key. A key kept only in the state directory would be lost with the disk.

Trust never comes from the bundle: `backup verify`, `backup restore` and `serve --restore` read the keys from the operator's config file and from `--trust-key` (`--restore-trust-key` for serve), which is how a host that has lost its config names one. A config file that exists but can't be parsed fails the command rather than turning the check off.

| Bundle | Trust keys configured | No trust keys |
| --- | --- | --- |
| Signed by a trusted key | `verified` | `unverified` |
| Signed by another key, or the signature is wrong | refused | `unverified` |
| No signature | refused, or `unsigned` with `--accept-unsigned` | `unsigned` |

`--accept-unsigned` admits only a bundle with no signature, never one whose signature fails. The result is reported as `authenticity`. With no trust keys nothing is checked, so existing bundles and runbooks keep working and the report says the bundle is not authenticated. An in-place restore checks trust only when it will restore, so a container restarting with `serve --restore` on a bundle it already restored keeps serving after a key rotation.

A scheduled backup whose signing key can't be resolved still publishes, unsigned, and raises the `backup_signing` diagnostic until signing works again: when the disk goes, a bundle that needs `--accept-unsigned` beats no bundle. `backup create` has an operator watching, so it fails instead, and `--unsigned` publishes without the key. It resolves references without starting packages, so a package-provided scheme works for scheduled backups only.

## Backup destinations

A package can store bundles off the host by declaring `backup_destinations` and implementing [`extension.BackupDestination`](https://github.com/open-conduit/open-conduit/blob/main/extension/backup.go) (`Put`, `List`, `Files`, `Read`), carried over the `backup_destination.*` methods in chunks of at most `MaxChunkBytes`. An independently installed package can do this the same way as the bundled `aws-s3` type, which stores bundles in an S3 bucket with the daemon's own AWS identity. `settings.backup.destinations` names each one, with a type and that type's config, which the package validates.

After publishing a scheduled bundle, the daemon ships it separately from the backup, so a slow or hung destination never delays the next local bundle or its pruning. Pruning leaves a bundle that is still being shipped until the next backup. The shipment puts its files to every destination: the data first, then the signature, then `manifest.json`. A file becomes visible only once all of it is stored, and a bundle counts as complete only once it holds its manifest, so one cut short is never listed. The daemon then checks that the destination holds every file at its size. A destination that makes no progress for 15 minutes is given up on for that attempt; the limit covers silence rather than the whole transfer, so a large bundle on a slow link still lands. A failure never fails the backup. It raises a `backup_destination` diagnostic naming how many files landed, records a `backup.shipped` telemetry event with the outcome, and is tried again 15 minutes later with the newest bundle, skipping a destination that already holds that bundle's files at their sizes, which takes one query about that bundle. A daemon that restarts checks its newest bundle the same way. Doctor's `backup_destinations` check reports each destination's latest outcome since the daemon started, and a signing key that has stopped working.

`backup list DESTINATION` names a destination's complete bundles, and `backup fetch DESTINATION BUNDLE DIR` downloads one into an absent directory, which `backup restore` then takes. A destination is untrusted, so a fetch needs a trust key or an explicit `--accept-unsigned`, even though a local restore with no trust keys is allowed. It accepts only a bundle's own file names, fetches the manifest and signature first and stops there if they fail, holds each file to the size the destination stated, and verifies the whole bundle before publishing the directory.

What a destination keeps, for how long and how it is encrypted are its owner's policy: Open Conduit doesn't prune a destination, and bundles reach it as they are, so server-side encryption is configured on the bucket. The size of a bundle is not covered by its signature, so a destination can make a fetch use disk up to what it states before the verification refuses it.

## Limits

Digests detect corruption and incomplete copies. A signature proves a trusted key made the bundle, but not that it is the newest: someone able to write where bundles are kept can put back an older genuine bundle. Bundles are not encrypted. Keep bundles owner-only because snapshots contain private Work/Event/configuration and executor continuity. Backups require a compatible schema/build. The live state they read must be on a local or block disk ([`internal/localfs`](https://github.com/open-conduit/open-conduit/tree/main/internal/localfs) refuses anything else). A bundle's destination may be a network mount, because a bundle has one writer and digests that detect a bad copy, but it is still a SQLite file plus renames and directory syncs, so its durability is that mount's and doctor's `filesystem` check warns about it. Power-loss guarantees depend on the filesystem and storage honoring flushes. Restore neither adopts a surviving external process nor authorizes a second scope owner; those remain runtime recovery responsibilities.

## Operator commands

`open-conduit backup create DEST [--unsigned]`, `backup verify BUNDLE` and `backup restore BUNDLE (--to DIR | --in-place) [--database-location LOC] [--artifacts NAME --artifacts-location LOC [--artifacts-command PATH]] [--trust-key KEYS] [--accept-unsigned]` run offline under the state directory's daemon lock ([`internal/bootstrap/state.go`](https://github.com/open-conduit/open-conduit/blob/main/internal/bootstrap/state.go)). `--in-place` ([`restore_inplace.go`](https://github.com/open-conduit/open-conduit/blob/main/internal/bootstrap/restore_inplace.go)) calls `backup.Restore` with a stage inside the daemon's own state directory as the destination, so the swap that follows renames on one filesystem. Under the lock it first removes stages earlier restores left before their swap began, and refuses to move the daemon off a database or artifact store its `storage.json` names outside the directory unless the operator names the new store. It then completes the stage (fresh token, `restored.json` with the bundle's database digest), journals the swap, moves the replaced items into `before-restore-*`, renames the staged ones in, removes the toolbelt run directories of executions the restored database doesn't know (`management.ForgetRuns`) and runs `state check`. A journal left by a swap that stopped makes the daemon and the other offline commands refuse the directory until the restore is run again, which finishes it. `serve --restore BUNDLE` runs the same restore before serving, skipping it when `restored.json` already names the bundle ([recovery](../recovery/#restoring-after-a-bad-release-or-lost-state)). A restore also revokes the bundle's operator credential and writes a fresh `private/operator.token` through the locked local reset (`auth recover`). It then reads the restored generation (`management.StoredGeneration`) and validates it as `management.OpenConfig` will at start, against the packages installed beside the config file (`--config FILE`, default the operator's), through the same helper `config check` uses. It reports the generation as `config_generation` and every diagnostic under `config_problems` (path, code, message), packages that couldn't start included; a check that can't run is one problem, `unchecked`. The report changes nothing. A generation with problems is one the daemon won't start from: it adopts a config file that validates over it, and otherwise refuses to start ([recovery](../recovery/#restoring-after-a-bad-release-or-lost-state)). `backup.Inspect` reads a manifest without verifying its bytes.

The running daemon also calls `backup.Create` on a schedule ([`internal/bootstrap/autobackup.go`](https://github.com/open-conduit/open-conduit/blob/main/internal/bootstrap/autobackup.go)), without stopping: every `--backup-interval` (default 24h) it publishes `conduit-<UTC time>` into `--backup-dir` (default `<data-dir>/backups`) and removes the oldest such bundles beyond `--backups-kept` (default 7). The [recovery](../recovery/#scheduled-backups) page has the details and the restore runbook.

Before its first start on a newer record format or schema, the daemon also calls `backup.CreatePrior` on the storage contract's `Backend.OpenPrior`, which holds the state as the older binary left it and snapshots it without writing. It commits no retention hold, because a hold is a write and the state directory's lock already keeps the sweep from running. The bundle is verified, published as `pre-upgrade-<UTC time>` outside the rotating set, and labelled in the manifest's `Build` (`<build> pre-upgrade records=N schema=N from=<build>`), which `backup.Inspect` parses. The label isn't a new manifest field because binaries already released decode manifests strictly and would refuse the bundle made for them ([recovery](../recovery/#the-bundle-taken-before-an-upgrade)).

Every other bundle names its record format the same way, as `<build> records=N` in `Build`, which `backup.Inspect` reads back as `Records`. `backup verify` and `backup restore` compare it with the backend's `Writes` once the manifest has passed trust, and refuse a bundle from a newer format (`stored records are newer than this binary writes`) before a stage is made or a byte is copied. A bundle from before this names no format, and is left to the backend's own check when the restored state is opened.

## Evidence

`go test -race ./internal/backup` exercises captured correlation/timer/history/content, exclusion of later live changes, lease fencing, existing-destination refusal, manifest/database/artifact corruption, missing-reference rejection, refusal of an omission on an unexpired Execution, a retention hold committed before the snapshot and held through every read then released (published or not), refusal without a hold, and a copy stopped by a failed renewal. `TestRestoreReportsTheConfigAndWhatItNeeds` restores a bundle onto a host with no config file and no packages, and checks that the restore reports the generation, the connection type nothing provides, and a diagnostic of another kind (a generation altered so a scope's parent is gone), with a generation that validates as its negative control. `TestTrustPolicy` covers every row of the signing table, `TestRestoreRefusesAForgedBundle` re-signs a bundle with another key, with the genuine bundle as its negative control, `TestRestoreUsesTheBytesItChecked` swaps the database for a forged one after the digest check and finds the genuine state restored, and `TestBundleTrustThroughTheCommands` runs signing, a rotated key and a stripped signature through the operator commands. `TestScheduledBundleIsShippedManifestLast` and `TestFailedShipmentIsReportedAndRetried` cover shipping, a failure that lands nothing listed, and the retry. `TestHungDestinationDoesNotStopBackups` keeps publishing and pruning while a destination never answers, keeps the in-flight bundle, and gives up on the stalled call. `TestFetchAuthenticatesTheBundle` refuses a fetch with no trust key, with the wrong key before the database is read and with a swapped database, with the genuine bundle as its negative control, and `TestFetchRefusesWhatADestinationCantMean` refuses paths outside a bundle. `TestS3PutListReadRoundTrip` runs the `aws-s3` type against a fake S3 that checks every request's signature and body digest. `TestRestoreInPlace` restores into a state directory with a later timeline: the replaced database and token are moved aside intact, the run directory of the execution the bundle doesn't know is removed and the bundle's kept, the executor's and extension's private state is reported and kept, the token is fresh and the check passes; `serve --restore`'s once leaves the directory alone and an explicit restore (the negative control) restores again. `TestRestoreInPlaceFinishesAnInterruptedSwap` stops a swap after its first move, checks that the directory is refused, and finishes it without a second restore. `TestRestoreInPlaceKeepsAnExternalStore` refuses to move a directory off an external artifact store unasked, with `--artifacts files` as its negative control, and refuses a database outside the directory. `TestRestoreInPlaceClearsStaleStages` removes and reports the stages killed restores left. `TestNewerBundleIsRefusedBeforeAnythingIsCopied` refuses a bundle from a newer record format from its manifest and leaves nothing beside the destination, with the binary that wrote it restoring the same bundle as its negative control. `TestRestoreInPlaceCommands` (in `internal/cli`) covers the flags, a `serve --restore` that doesn't serve after a failed restore or check, and `service install` refusing `--restore`. `TestShellRetentionReleasesRunDirectories` runs the retention sweep on real shell attempts, then backs up and restores, with the expired attempt's references omitted. SQLite and artifact suites separately exercise process kill/reopen and transaction/publication fault boundaries. No composed-daemon drill exercises the offline commands since `TestDaemonMigrationRehearsal` went with the migrator in [#413](https://github.com/open-conduit/open-conduit/pull/413).

## History

:::note
These notes record how this part was built and the evidence gathered at each stage. They describe the code at the time; the sections above describe current behaviour.
:::

- Ticket 02-01 implemented backup composition alongside SQLite and artifacts as backend APIs and tested bundle mechanics. Operator commands and recovery runbooks were left to 06-02, and instance credentials/config were left to later bootstrap work.
- Ticket 06-02 added the `open-conduit backup` commands, the restore-time operator credential reset, the [recovery](../recovery/) runbooks and `TestDaemonMigrationRehearsal`.
- Until [#352](https://github.com/open-conduit/open-conduit/issues/352), bundles were made only by the offline `backup create`; the daemon now makes them on a schedule while it runs.
- Until [#37](https://github.com/open-conduit/open-conduit/issues/37), `Create` copied every reference, so a backup failed with "not found" once the retention sweep had released any attempt's content. Expired references are now recorded as omitted.
- Until [#774](https://github.com/open-conduit/open-conduit/issues/774), `Create` pinned the file artifact store with an in-process lock while it copied, and retention and collection waited for the backup to end; a hold in coordination replaced it, and `Create` and `Restore` take any artifact store.
- Until [#700](https://github.com/open-conduit/open-conduit/issues/700), a restore only wrote a new directory, and putting it back where the daemon ran was a manual swap of the database, its side files, the artifacts and the token.
- Until [#699](https://github.com/open-conduit/open-conduit/issues/699), these pages said a bundle held no config, and a restore didn't say which packages its generation needed.
- Until [#698](https://github.com/open-conduit/open-conduit/issues/698), digests were the only check on a bundle, and any self-consistent bundle restored; and bundles stayed on the host unless the operator built a job to copy them.
- Until [#767](https://github.com/open-conduit/open-conduit/issues/767), `Create` and `Restore` took the SQLite store and called SQLite's backup and restore directly; they now work over the storage lifecycle contract, and the manifest names a non-default backend.
